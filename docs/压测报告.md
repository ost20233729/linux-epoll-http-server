# minihttpd 压测报告

> 2026-09-17 实测（POST 上传 / CGI / 配置热加载功能合入后的版本，commit 775a6b3）。
> 目标：验证自研 HTTP 服务器的吞吐能力，为面试提供真实性能数据。

## 环境

| 项 | 值 |
|---|---|
| 服务器 | 阿里云 ECS（华南3广州） |
| 配置 | 2 核 / 1.6 GB 内存 |
| 系统 | Ubuntu 24.04 |
| 服务 | minihttpd（自研 C 语言 epoll 单线程事件循环，含 POST/CGI/热加载） |
| 压测工具 | wrk 4.1.0（与服务器同机，回环网络） |
| 页面 | 首页 index.html（约 6KB，含内联样式） |

## 结果

| 并发连接数 | 线程数 | 时长 | QPS | 平均延迟 | 最大延迟 |
|---|---|---|---|---|---|
| 100 | 2 | 30s | 2,438 | 41.0ms | 61.2ms |
| 500 | 4 | 30s | **11,837** | 42.1ms | 108.8ms |

- 500 并发下零错误、零超时
- 传输速率峰值 67 MB/s（回环带宽不构成瓶颈，瓶颈在 CPU）
- 对比合入 POST/CGI/热加载前的版本（11,802 QPS）：**新功能无性能开销**

## 公网压测（本地虚拟机 wrk → 阿里云）

| 项 | 值 |
|---|---|
| 客户端 | wrk 4.1.0（本地 Linux 虚拟机，家用宽带，VMware NAT） |
| 网络路径 | 家用宽带 → 公网 → ECS 公网 IP:8080 |
| 页面大小 | 6352 字节 |

| 并发连接数 | 线程数 | 时长 | QPS | 平均延迟 | 最大延迟 |
|---|---|---|---|---|---|
| 50 | 2 | 30s | 459 | 112ms | 709ms |
| 100 | 2 | 30s | **758** | 154ms | 1.01s |

- 零错误、零超时；传输速率 2.87 ~ 4.73 MB/s（约 23~38 Mbps）
- 平均延迟与利特尔法则吻合（100 并发 ÷ 758 QPS ≈ 132ms ≈ 实测 154ms）

公网吞吐远低于回环（67 MB/s）——瓶颈是**公网网络路径**（ECS 公网带宽与家用宽带上行），而非服务器本身：带宽足够时（回环）服务器可跑到 1.2 万 QPS。

## 零拷贝 A/B 实测（sendfile 开关对比）

| 项 | 值 |
|---|---|
| 方法 | 环境变量 `MINIHTTPD_NO_SENDFILE=1` 切换发送路径（read+send vs sendfile） |
| 测试文件 | 50 MB 随机数据 |
| 并发 / 时长 | 8 连接 × 30s，回环 |

| 模式 | QPS | 传输速率 |
|---|---|---|
| sendfile 开启 | 15.47 req/s | 1.01 GB/s |
| sendfile 关闭（read+send） | 14.66 req/s | 0.96 GB/s |

**结论：该场景下 sendfile 零拷贝吞吐提升约 5.5%。**
回环带宽充裕（1 GB/s 未触顶），差异来自拷贝路径本身（sendfile 少两次内核拷贝与上下文切换）；
公网场景带宽受限时该差异会被带宽瓶颈掩盖。CPU 用户态占用两模式均接近 0（拷贝在内核完成）。

## 结论

- **服务器能力**：在 2 核 1.6G 的低配云服务器上，单线程 epoll 架构的 minihttpd 达到 **约 1.2 万 QPS**（回环），零错误，瓶颈为单线程 CPU。
- **公网场景**：实测 100 并发约 **760 QPS**、零错误——公网部署时**网络带宽是第一瓶颈**，服务器计算能力远未触达上限。
- 当前负载形态为静态文件 + 进程级 CGI 隔离，单线程事件循环尚未触达瓶颈。

## 复现命令

```bash
apt-get install -y wrk
wrk -t 4 -c 500 -d 30s http://127.0.0.1:8080/
```
